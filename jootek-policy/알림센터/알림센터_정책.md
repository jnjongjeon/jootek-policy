# 7. 알림센터

# 1. 범위

- 알림 목록 조회
- 읽음 / 안 읽음 상태 관리
- 안 읽은 알림 수 제공
- 알림 전체 읽음 처리
- 알림 유형 및 읽음 상태 필터
- 알림 발생일 기준 목록 구분
- 알림 유형별 정보 제공
- 알림 선택 시 관련 기능 연결
- 알림 내 직접 액션 제공
- 알림 발생시간 표시
- 알림 목록 상태 처리
- 기존 알림 데이터 연결

# 2. 정책 및 동작

## 2-1. 기본 정책

- `마이주택 > 알림`은 Member에게 발생한 서비스 알림을 확인하고 관리할 수 있는 개인 알림 목록으로 제공한다.
- 알림은 수신 대상 Member를 기준으로 제공한다.
- 모든 Member가 알림 기능을 이용할 수 있다.
- **알림의 생성 조건, 수신 대상, 알림 문구는 각 기능의 알림 Feature Task를 SSOT로 따른다.**
- 본 Task에서는 각 Feature Task에 따라 이미 생성된 알림의 **조회·표시·읽음 처리·필터·연결 동작**을 정의한다.
- 본 Task에서 알림 유형이나 예시를 명시하더라도 해당 알림의 새로운 생성 조건을 정의하지 않는다.
- 알림은 발생 시점의 알림 내용과 발생시간을 기준으로 목록에 제공한다.
- 동일한 상태 변경 이벤트로 생성되는 알림은 중복하여 생성하지 않는다.

## 2-2. 알림 목록

- 현재 Member에게 발생한 알림을 목록 형태로 제공한다.
- 알림은 최신 발생 순으로 제공한다.
- 알림 목록은 발생일을 기준으로 `오늘 / 이전`으로 구분한다.
- `오늘`에는 현재 날짜에 발생한 알림을 제공한다.
- `이전`에는 오늘 이전에 발생한 알림을 제공한다.
- 각 구간에서도 최신 발생 순으로 제공한다.
- 각 알림은 읽음 여부를 구분하여 제공한다.
- 안 읽은 알림은 별도의 상태 표시를 제공한다.
- 상단에서 현재 안 읽은 알림 수를 제공한다.
- 알림 목록에서는 `모두 읽음` 기능을 제공한다.

### 기본 표시 정보

각 알림에는 알림 유형에 따라 다음 정보를 조합하여 제공한다.

- 알림 아이콘
- 알림 제목
- 알림 맥락정보 또는 설명
- 알림 발생시간
- 읽음 상태
- 필요한 경우 직접 액션

## 2-3. 알림 유형

알림센터의 조회 및 필터를 위해 다음 유형으로 구분한다.

| 알림 유형 | 주요 대상 |
| --- | --- |
| 문의 | 문의 관련 알림 |
| 회사 | 회사 등록·소속·회사 정보·비즈니스 페이지 관련 알림 |
| 활동 배지 | 전문가 인증 등 Member 활동 자격 관련 알림 |
| 기타 | 위 유형에 포함되지 않는 서비스 알림 |
- 알림 유형은 알림 목록의 분류 및 필터 기준으로 사용한다.
- 각 알림은 해당 알림을 발생시킨 기능에 맞는 유형으로 분류한다.
- 필터에서 `문의 / 회사 / 활동 배지 / 기타`를 제공한다.
- **각 유형에 실제로 어떤 이벤트의 알림을 생성하는지는 해당 알림 Feature Task를 따른다.**

## 2-4. 문의 알림

- 문의 알림의 생성 조건 및 수신 대상은 P-03 문의 알림 정책을 따른다.
- 알림센터에서는 생성된 문의 알림에 필요한 문의 맥락정보를 제공한다.
- 문의자에게 전달되는 알림은 관련 문의 또는 문의 목록으로 연결한다.
- Company 측 Member에게 전달되는 알림은 Company 문의 내역 또는 해당 문의로 연결한다.
- 개별 문의를 특정할 수 있는 알림은 해당 문의 맥락으로 연결한다.
- 여러 문의를 묶어서 안내하는 알림은 관련 문의 목록으로 연결한다.
- Company명, 문의 유형, 문의자 닉네임, 지번 주소 등 구체적인 맥락정보의 구성은 해당 문의 알림 정책을 따른다.

## 2-5. 회사 알림

- 회사 알림의 **생성 조건·수신 대상·문구는 P-01 `회원·회사 체계 알림` 및 P-02 `전문가기업정보 알림`을 따른다.**
- 알림센터에서는 해당 정책에 따라 생성된 회사 관련 알림을 `회사` 유형으로 제공한다.

현재 연결되는 주요 알림 범위는 다음과 같다.

### P-01 회원·회사 체계

- 회사 등록 승인
- 회사 등록 반려
- Company 소속 초대
- Company 소속 해제
- 기타 P-01 알림 정책에서 생성 대상으로 정의한 회사 관련 알림

### P-02 전문가기업정보

- 회사 정보 수정 신청 완료
- 회사 정보 수정 승인
- 회사 정보 수정 반려
- 폴리오 입점 신청 완료
- 폴리오 입점 승인
- 폴리오 입점 반려
- 반려 사유 제공 여부 및 클릭 목적지는 각 원본 알림 정책을 따른다.
- 본 Task에서 별도의 회사 알림 생성 조건을 추가하지 않는다.

## 2-6. 활동 배지 알림

- 전문가 인증 등 Member 활동 자격과 관련하여 생성된 알림을 `활동 배지` 유형으로 제공한다.
- 전문가 인증 알림의 생성 조건, 수신 대상, 문구 및 연결 동작은 P-01 `회원·회사 체계 알림`을 따른다.
- 알림센터에서는 해당 정책에 따라 생성된 전문가 인증 알림을 조회할 수 있도록 한다.
- 전문가 유형, 반려 사유 등 알림별 표시 정보는 원본 알림 정책에서 정의한 범위를 따른다.
- 본 Task에서 별도의 전문가 인증 알림 생성 조건을 추가하지 않는다.

## 2-7. 알림 내 직접 액션

- 별도의 상세 페이지 진입 없이 즉시 처리가 필요한 알림은 알림 항목에서 직접 액션을 제공할 수 있다.
- 직접 액션 제공 여부와 실제 처리 결과는 해당 기능의 정책을 따른다.
- 현재 직접 액션 대상으로 `Company 소속 초대`를 제공한다.
- 유효한 Company 소속 초대 알림에서는 `수락 / 거절`을 제공한다.
- `수락` 선택 시 해당 소속 초대를 수락한다.
- `거절` 선택 시 해당 소속 초대를 거절한다.
- 초대가 처리되거나 더 이상 유효하지 않은 경우 기존 `수락 / 거절` 액션을 수행할 수 없도록 처리한다.
- 소속 수락·거절 자체의 도메인 처리 기준은 P-01 `소속 회원 등록` 정책을 따른다.

## 2-8. 읽음 상태

- 각 알림은 `읽음 / 안 읽음` 상태를 가진다.
- 새로 발생한 알림은 안 읽음 상태로 제공한다.
- 안 읽은 알림은 목록에서 별도 상태 표시로 구분한다.
- 안 읽은 알림 수를 알림 목록 상단에 제공한다.
- Member가 알림을 확인하면 해당 알림을 읽음 상태로 변경한다.
- `모두 읽음` 선택 시 현재 Member의 안 읽은 알림 전체를 읽음 상태로 변경한다.
- 읽음 처리된 알림은 목록에서 삭제하지 않고 읽음 상태로 제공한다.
- 읽음 상태가 변경되면 안 읽은 알림 수를 갱신한다.
- 한 Member의 읽음 처리는 다른 Member의 알림 읽음 상태에 영향을 주지 않는다.

## 2-9. 필터

- 알림 목록에서 원하는 알림을 조회할 수 있도록 필터를 제공한다.
- 필터는 `알림 유형 / 읽음 상태`를 기준으로 구성한다.

### 알림 유형

- 문의
- 회사
- 활동 배지
- 기타

### 읽음 상태

- 읽음
- 안 읽음
- 선택한 필터 조건에 해당하는 알림만 목록에 제공한다.
- 알림 유형과 읽음 상태 조건을 함께 적용할 수 있다.
- 적용된 필터 조건은 목록 조회에 반영한다.
- 필터를 초기화하면 전체 알림 목록으로 돌아간다.

## 2-10. 알림 발생시간

- 각 알림에는 알림이 발생한 시간을 제공한다.
- 발생시간은 현재 시각과의 차이에 따라 상대시간 또는 날짜 형식으로 제공한다.
- 발생시간이 경과함에 따라 현재 기준에 맞는 표시 형식으로 변경한다.

| 기준 | 표시 형식 | 예시 |
| --- | --- | --- |
| 경과시간 60분 미만 | `N분 전` | `5분 전`, `42분 전` |
| 경과시간 60분 이상 + 동일 날짜 | `N시간 전` | `2시간 전`, `8시간 전` |
| 전일 | `어제` | `어제` |
| 전일보다 이전 + 동일 연도 | `MM.DD` | `09.15` |
| 현재 연도 이전 | `YYYY.MM.DD` | `2025.12.31` |

## 2-11. 목록 상태 처리

### 알림 없음

- Member에게 제공할 알림이 없는 경우 Empty State를 제공한다.
- `표시할 내용이 없습니다.`를 제공한다.

### 필터 결과 없음

- 적용한 필터 조건에 해당하는 알림이 없는 경우 결과 없음 상태를 제공한다.
- `검색 결과가 없습니다.`와 조건 변경 안내를 제공한다.
- 적용한 필터 조건은 유지한다.

### 로딩

- 알림 목록을 조회하는 동안 Skeleton UI를 제공한다.
- 조회 완료 후 결과에 따라 알림 목록, Empty State 또는 필터 결과 없음 상태를 제공한다.

## 2-12. 기존 알림 데이터 연결

- 기존 Member에게 발생한 알림은 신규 `마이주택 > 알림` 구조에서 현재 Member와 연결하여 제공한다.
- 기존 알림의 읽음 / 안 읽음 상태를 유지하여 제공한다.
- 알림센터 구조 개편만을 이유로 기존 알림을 삭제하거나 동일 알림을 새로 생성하지 않는다.

# 3. 상태/조건별 처리 기준

## 3-1. 알림 읽음 상태

| 상태/조건 | 처리 |
| --- | --- |
| 신규 알림 발생 | 안 읽음 상태로 목록에 추가 |
| 안 읽음 | 상태 표시 제공 및 안 읽은 알림 수에 포함 |
| 알림 확인 | 해당 알림 읽음 처리 |
| 읽음 | 안 읽음 표시 제거, 목록에는 유지 |
| `모두 읽음` 선택 | 현재 Member의 안 읽은 알림 전체 읽음 처리 |
| 모든 알림 읽음 | 안 읽은 알림 수 `0`으로 갱신 |

## 3-2. 알림 발생일

| 발생 시점 | 목록 구분 |
| --- | --- |
| 오늘 발생 | `오늘` |
| 오늘 이전 발생 | `이전` |
- 각 구간에서는 최신 발생 알림을 우선 제공한다.

## 3-3. 알림 유형별 처리

| 유형 | 주요 정보/동작 |
| --- | --- |
| 문의 | 문의 알림 정책에 따라 생성된 알림 표시 및 관련 문의 연결 |
| 회사 | P-01/P-02 회사 관련 알림 표시 및 관련 기능 연결 |
| 활동 배지 | P-01 전문가 인증 관련 알림 표시 및 관련 기능 연결 |
| 기타 | 해당 Feature Task에서 생성된 기타 서비스 알림 표시 및 연결 |

## 3-4. 문의 알림 연결

| 알림 조건 | 처리 |
| --- | --- |
| 개별 문의 특정 가능 | 해당 문의 맥락으로 연결 |
| 여러 문의 묶음 안내 | 관련 문의 목록으로 연결 |
| 문의자 대상 알림 | 문의자의 관련 문의 또는 문의 목록으로 연결 |
| Company 측 알림 | Company 문의 내역 또는 해당 문의로 연결 |

## 3-5. 소속 초대 액션

| 상태/조건 | 처리 |
| --- | --- |
| 유효한 소속 초대 | `수락 / 거절` 제공 |
| 수락 | 소속 초대 수락 처리 |
| 거절 | 소속 초대 거절 처리 |
| 초대 처리 완료 | 기존 수락/거절 액션 수행 불가 |
| 이미 유효하지 않은 초대 | 수락/거절 불가 |

## 3-6. 필터 상태

| 상태/조건 | 처리 |
| --- | --- |
| 필터 미적용 | 전체 알림 제공 |
| 알림 유형 선택 | 해당 유형의 알림 제공 |
| 읽음 선택 | 읽은 알림 제공 |
| 안 읽음 선택 | 안 읽은 알림 제공 |
| 유형 + 읽음 상태 선택 | 두 조건을 모두 충족하는 알림 제공 |
| 필터 결과 없음 | 결과 없음 상태 제공 |
| 필터 초기화 | 전체 알림 목록 제공 |

## 3-7. 목록 상태

| 상태/조건 | 처리 |
| --- | --- |
| 알림 있음 | 알림 목록 제공 |
| 알림 없음 | Empty State 제공 |
| 필터 결과 없음 | 필터 결과 없음 상태 제공 |
| 조회 중 | Skeleton UI 제공 |
| 조회 완료 | 결과에 따라 목록 / Empty State / 필터 결과 없음 제공 |
